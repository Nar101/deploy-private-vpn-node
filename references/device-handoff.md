# 跨设备文件交付

## 默认选择文件，不依赖自动同步

Shadowrocket iCloud 可能出现旧设备反向覆盖、保存态与运行态不同或同步时间不明确。默认用 AirDrop、Finder 或用户自己的受控文件通道交付；自动同步保持关闭，除非用户明确选择它并接受覆盖风险。

## 交付包结构

```text
node.txt       # 仅含新节点，包含连接凭证
rules.conf     # 规则与代理组，不包含 SSH 私钥
README.txt     # 导入与验证步骤
SHA256SUMS     # 文件完整性
```

节点与规则分开，避免导入单节点时覆盖整份配置。文件名使用 ASCII，减少 iPhone 解压与跨平台兼容问题。使用 `scripts/build-transfer-package.sh` 生成，压缩包与源文件权限为 `600`。

## 安全边界

- SSH 私钥永远不进入设备交付包。
- 节点文件包含 UUID、public key、short ID 等连接凭证，只在用户自己的设备之间传输。
- 不上传聊天群、公开仓库或公共网盘。
- 生成后运行私钥特征扫描；命中即阻断。
- 交付完成不自动删除源文件，先由用户确认设备导入和备份策略。

## 每台设备的完成证据

1. 导入节点文件，不覆盖现有节点。
2. 导入规则文件并确认选择了正确配置。
3. 回读节点端口、SNI、flow 和 Reality 字段。
4. 原生节点测速出现成功结果。
5. 出口 IP 等于新 VPS。
6. 目标服务返回预期 HTTP 状态。

“已 AirDrop”“文件可打开”或“节点出现在列表”都不等于设备可用。
